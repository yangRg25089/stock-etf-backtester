# 复用与组织规范

本文件定义 V1 唯一的策略目录、参数归属、运行状态、界面组件、模块接口和工作顺序。交易与财务计算的具体规则以[回测器设计稿](../superpowers/specs/2026-09-28-stock-etf-backtester-design.md)为准。实现时同一概念只保留一个字段定义和一个计算入口；预设只提供参数，不复制算法。

## 策略目录与计算模块

| 目录 ID / 用户可见类型 | 执行模块 | 差异仅来自配置 |
| --- | --- | --- |
| `vix_dca` / VIX 信号定投 | `accumulation` | 默认仅启用 VIX 买入信号；代码、阈值和信号月限可编辑，默认不卖出 |
| `composite_dca` / 多条件定投 | `accumulation` | 买入信号集合、AND/OR、固定比例定投、卖出规则 |
| `ma_trend` / MA 买卖 | `trend` | `sellBelowOrEqualMa=true` |
| `ma_buy_only` / MA 只买 | `trend` | `sellBelowOrEqualMa=false` |
| `monthly_dca` / 定额月度定投 | `scheduled` | `fundingMode=monthly` |
| `lump_sum` / 一次性投入 | `scheduled` | `fundingMode=upfront` |
| `grid_search` / 网格搜索 | `search` 作业包装 | 实例持有一份 `accumulation` 基础参数和搜索维度，候选仅覆盖所选键；每一候选调用普通校验/执行/指标模块 |

自动显示的 DCA 与一次投入基准分别使用 `monthly_dca`、`lump_sum` 的同一参数、账本和指标模块，结果角色为 `benchmark`。用户添加同种策略时角色为 `strategy`、实例 ID 独立；相同计算指纹可复用结果，但不能把两行身份混成一个实例。搜索也不拥有独立的交易规则。

目录中的用户可见名称表示预设类型，不锁定实例参数。`vix_dca` 的日文 UI 名称为「ボラティリティ積立」，首屏摘要显示当前配置（例如 `VIX: ^VIX ≥ 25、月間最大 1 回`）；`vix.buyEnabled`、`vix.symbol`、`vix.buyThreshold` 和相关买入次数都可以编辑，其中 `vix.symbol` 只能从真实 Yahoo 验证可用的 `^VIX`、`^VXN`、`^VXD` 选项中选择。关闭 VIX 信号时仍保留 `presetId=vix_dca` 和实例身份，界面明确显示「VIX シグナル無効」，不静默改成另一种策略；空买入信号集合按统一信号规则处理。

首屏 VIX 信号定投是上述目录中的普通预设，可删除后重新添加。UI 同一预设最多一个实例，已添加选项禁用且 reducer 防重；后端仍允许历史多实例，恢复结果不合并身份。实例参数相互独立；复用的是字段定义、输入组件和算法，不是用户编辑中的数值。

## 唯一参数注册表

成交假设的唯一共享键为`execution.commission`、`execution.slippagePct`、`execution.spreadPct`和`execution.fractionalShares`；默认值0/0/0/true、范围、单位与翻译均来自后端目录，不作为策略独立参数或搜索维度。catalog-v14追加此组字段，旧catalog-v12/v13文件可通过显式兼容读入：只补可编辑草稿的新目录默认值，不改保存结果、版本或旧缺失成本。共同成交及资金/NAV语义见主设计稿，UI只格式化保存值。

后端的 `ParameterDefinition` 注册表是默认值、类型、单位、取值范围、适用目录、可搜索性、依赖、字段分组 ID 和日中翻译键的唯一维护点；catalog 同时提供分组 ID 与本地化标题。前端按该元数据组织策略参数，不从字段键名推测分组。前端通过目录接口取得元数据并渲染字段；服务端用同一注册表完成最终校验。TypeScript 结构类型由服务端公开契约生成，不在前端另写默认值或边界。跨字段约束（如 VIX 阈值顺序、搜索组合数）也集中在一次配置校验中。所有配置键稳定、不翻译。

`type` 只允许 `symbol | date | integer | decimal | ratio | percent_point | boolean | enum | enum_list | number_list`。`ratio` 在保存和计算中恒为 0 至 1，编辑器显示等值的百分数（如 0.2 显示 20%）；显示值、范围和步长从注册元数据做十进制移位，提交还原原比例，不四舍五入掩盖非法精度。`percent_point` 以 2.5 表示 2.5%，不能有的字段存 `0.025`、有的存 `2.5`。金额是数值，币种来自所选标的的行情元数据；代码和日期不显示无意义单位，数值单位以内嵌尾缀呈现，金额字段用说明解释其按标的报价币种计价。空值、非法范围与无适用性是三种不同校验结果。

注册表还要定义每项的具体上下界、步长和必要性；例如 `contribution.day` 为整数 1..31、比例 0..1、标准差倍数 >0、周期为正整数、金额不小于 0、搜索列表非空且去重。参数表的普通编辑器、搜索维度编辑器、服务端错误字段路径与导出配置快照都使用这些稳定键。前端始终提交全部已添加策略，运行范围不再是 UI 状态或注册参数；后端 API 保留历史请求契约。语言选择不包含在算法哈希里。

网格搜索实例中的基础参数用 `accumulation` 同一字段定义与默认值，在渲染时增加 `SearchDimensionEditor`：维度用可切换按钮，所选维度显示候选值卡片及总组合数。未被列为维度的字段保留该实例的基础值；列为维度的键逐候选覆盖，不能维护第二套搜索专用阈值或交易规则。候选列表的稳定键由 catalog `SearchDimension.valuesParameterKey` 绑定，默认值只维护在参数注册表。所选列表不得空、重复、非数字或越界；未选列表保留编辑内容，但不校验或参与枚举。提交时冻结列表，结果维度、候选曲线、CSV 与恢复均读取保存值；计算缓存指纹不含搜索包装配置。旧 catalog 的无绑定维度使用其已保存值。

## 草稿、作业与结果状态

股票代码的格式是共享领域约束 `SYMBOL_PATTERN`（1–32 个 ASCII 字母、数字及 `.^=_-`），catalog 的 symbol 字段通过 `pattern` 暴露同一约束；运行/数据契约共用 `Symbol`，不各自维护 regex。注册日期只接受 date，不接受 datetime；搜索列表必须非空且唯一。目录版本为 `catalog-v13`，已保存旧运行保留原目录指纹和原结果；v12 仅缺新增共享分析配置，显式迁移时只填入可编辑草稿默认值。

### 阶段 21 的当前约束

日期默认今天，标的提供 ETF 快捷选项及自由输入；金额统一从共通标的报价币种取得。活动目录不再提供最近完整日模式、固定比例定投或相对 DCA 差额。弹窗持有本地缓冲/校验，错误或校验未结束不能退出；关闭合法弹窗才更新草稿，播放按钮及保存结果完全不读取编辑缓冲。买入限额置顶。实例添加即运行，无启停草稿/control；固定类型防重，自定义最多 10 个、稳定编号；条件类型在每棵买/卖树内防重。比较行通过点击/键盘切换，多选无 checkbox；候选资产轨迹在计算时保存、查看时按需读取。停止 API 使用 cancelled 终态，保存已完成结果；SSE 提供真实逐策略进度与完成指标。下文阶段 20 及更早的相应启停、重复条件、固定比例/差额规则只作历史背景。

### 文件与读取边界（阶段35）

- 文件格式 `stock-etf-backtester`，首版 `schemaVersion=1`。策略文件只含 format/schemaVersion/type/exportedAt/catalogVersion/draft；回测文件额外保存 engineVersion、冻结 config、完整 RunResponse、全部 candidateDetails 和 dataProvenance。后端 `/runs/{id}/package` 只读取进程内记录；客户端文件加载无需写回 API。
- `features/files` 负责文件校验、预览和显式确认；`strategies/draftReader` 负责目录成员与条件结构，`api/contractReader` 复用生成的 JSON Schema 校验 HTTP 和文件结果。不接受成功指标缺失、失败诊断缺失、残缺/重复候选及不完整排名；业务参数校验仍使用现有 config API。
- 局部失败的回测文件保留所有冻结的失败输入和成功结果。仅对保存结果中明确 `failed` 的策略允许恢复有误的标量参数或重复条件类型，供编辑修正；策略文件仍须通过普通草稿读取。目录成员、对象结构、深度/节点预算及节点身份防重不放宽。旧平面参数在编辑器中按现有字段定义展示，修正前不允许关闭弹窗；修正不会改写旧结果。
- 文件上限64 MiB，JSON最多2,000,000个值、64层、单数组250,000项、单字符串65,536字符、key256字符；拒绝危险对象键和非有限数值。候选总数≤10,000；策略数量、条件树深度/节点、固定类型防重及自定义上限使用 catalog。Decimal指数绝对值≤4096，避免离线导出进行无界字符串展开。
- 新格式没有可迁移的已发布旧文件版本：0/未知旧版准确拒绝，未来版本提示过新；目录版本不一致拒绝，不能静默丢弃未知参数。上次受理配置记录单独使用 v1 key，不把旧的实时草稿记录当作实际运行记录迁移。
- 取消预览不改变工作区；合法确认后一次替换。策略文件清空结果，回测文件加载独立 imported 结果；再次导入同一 runId 也重置焦点、选择、图例、缩放及弹窗状态。执行中禁用文件操作；导入不写 last-run 配置。
- 导入结果的候选、CSV和PNG取文件内保存值，不请求运行服务，不重算交易或指标。CSV字段顺序与数值字段元数据由后端生成，Decimal保留精度，数组参数采用 JSON。身份、代码及文本不按数字格式转换。
- 绩效分析的年/月序列与回撤区段在统一metrics边界生成；年度表、月度热图及回撤表只展示保存值，年度DCA读取同一作业的基准。文件/CSV不重新计算；历史缺字段保持缺失。期间记录实际日期、不年化，回撤持续/恢复日数为日历日，图表显隐不改变分析。

### 阶段 20 条件契约（当前用户要求覆盖早期七类/平面组合限制）

阶段35运行预校验：已确认的工作区配置变更后300ms调用同一验证API，迟到响应按草稿身份和取消信号丢弃；弹窗内部缓冲不参与预校验。预校验仅控制运行入口及左侧诊断，不修改或清空已保存结果；点击运行仍通过后端受理校验。此规则落实新路线Task105，保留用户要求的弹窗与运行结果隔离。

- 策略增加可选 `rules: {buy, sell}`。根节点和子节点复用同一条件对象：叶节点 `{type:condition, id, kind, enabled, params}`；分组 `{type:group, id, enabled, operator:AND|OR, children}`。买入/卖出树独立；组表达括号，不根据控件排列猜测运算优先级。空树/空组为 false，停用子节点不参与布尔组合或数据依赖；任何启用必需叶节点 unavailable 仍阻断该策略，OR 不跳过它。
- 条件种类为 VIX、RSI、均线偏离、均线趋势、布林带、利率和 PE。同一买入树或卖出树内，条件类型不可重复；买卖两侧可各用一次，`id` 在同一策略买卖树内唯一；结构上限统一为 8 层、96 节点，目录返回限制，前后端共享。参数继续使用注册表稳定键、类型、边界、单位和默认值；叶节点只可使用其种类/方向允许的键，不能塞入其它策略字段。
- 基础目录新增 `rsi_dca`、`ma_deviation_dca`、`bollinger_dca`、`rate_dca`、`pe_dca`，与既有 VIX/MA 买卖/MA 只买共同提供固定模板：不可添加类型、AND/OR 或分组，只调整该模板参数/买卖启停。两个自动基准仍不可选，搜索继续使用共享规则。
- `composite_dca` 稳定 ID 改为用户可见「自定义策略」，不再提供旧复合编辑器；固定和自定义均用同一条件对象、ConditionCard 和评估入口。目录为十二类而非早期七类；旧结果身份、参数和算法指纹保留，不在恢复时重算。旧平面输入仅在配置边界物化成条件对象。
- 卖出树只在整棵树为 true 时成交：AND 汇总全部命中叶节点，OR 汇总为 true 的分支；取其中最大卖出比例，不相加。VIX 叶节点仍在低档优先规则下给出一档比例；RSI/布林沿用原公式/比例，MA 趋势固定模板退出全部择时仓。自定义新增的均线偏离/利率/PE 卖出分别使用买入比较的反向 `>=`（有效正 PE），通过共享 `exit.ratio` 配置比例；买入与卖出依赖/参数完全独立。
- 提交冻结完整条件树、独立参数、catalog/data/engine 指纹；进程内冻结叶节点 Decimal，文件使用统一 JSON 契约。验证错误路径包含节点 ID/参数稳定键，UI 可定位，导出来自保存结果。普通运行、固定模板、自定义和搜索复用条件评估/账本；搜索所选稳定参数键在候选条件树中覆盖该键的所有适用叶节点，未选键保持各叶节点原值。
- 配置校验边界按注册表类型读取精确 Decimal JSON 字符串，包括平面参数、买卖条件和搜索数值列表；保存、刷新、导入后再次运行复用同一解析函数，不经 JavaScript 浮点转换。合法数值文本使用十进制/科学计数法，Decimal 实际指数（显式指数减小数位数）绝对值≤4096；空值、空白、NaN、无穷、布尔或含单位的文本仍给出字段诊断；代码、枚举、整数和布尔不按外观猜测类型。

| 状态实体 | 唯一含义 |
| --- | --- |
| `StrategyInstance {id, presetId, instanceNumber, params, rules}` | 添加即参与运行；弹窗缓冲通过校验后一次提交；自定义最多十个，序号不因删除改变 |
| `activeStrategyId` | 保留的内部单实例 API 目标；UI 不显示范围/目标选择，dialog 编辑对象独立，不自动启用或运行 |
| `runScope` | UI 固定 `all_enabled`，API 仍支持 `active`；当前实例必须存在才能单独运行，全部模式至少有一个实例；所选范围之外的实例不参与本次运行 |
| `RunSnapshot {runId, config, catalogVersion, engineVersion, submissionFingerprint, createdAt, dataContext}` | 受理时冻结原始配置和提交身份；queued 时 dataContext 为 null，后台加载后一次绑定实际数据上下文，原配置和提交时间不改写 |
| `RunDataContext {dataFingerprint, dataProvenance, effectiveRun, dateAdjustments}` | 已加载数据的真实指纹、来源和解析后的实际区间；内核/CSV 使用 effectiveRun，不能用提交指纹充当数据指纹 |
| `StrategyRun` | 该快照中的实例状态、诊断、账本、指标、交易和信号观测值；每日资产保留可选的调整后 OHLC；`benchmark` 是角色字段，不是第二套算法 |
| `focusedResultId` | 交易、搜索、保存身份和导出的归属；与 `activeStrategyId` 及曲线多选独立 |
| `selectedResultIds` | 仅决定主图中的策略资产收益曲线；焦点/运行范围独立，取消全部时仍保留价格 |
| `visibleSeriesIds` | 只控制曲线显隐，不改变结果或运行范围 |

作业及每条策略的状态码由后端给出：`queued | loading | running | completed | completed_with_warning | unavailable | failed | cancelled`。`empty` 是结果页没有作业时的显示状态，不伪装成失败；零交易但指标完整仍是 `completed`。前端不可从“是否含 PE”自行推断失败，必须展示统一诊断码。全体失败与部分成功分别呈现。结果保留策略身份，保存标的/期间在按需信息入口可查；草稿变化不改变右侧显示或诊断，不生成旧输入提醒。配置校验仅归属设置侧；播放或显式文件导入更新结果，重置只清空当前页面显示。

运行响应、幂等认领及候选详情只保存在后端进程内存；服务重启全部清空。页面初始化查询 `/runs/active`，仅接回 queued/loading/running 作业；终态运行不自动恢复。

浏览器在成功受理后写入 `stock-etf-backtester.last-run-strategy.v1`；后台加载得到日期解析后，用同一已保存运行的实际区间更新该配置记录，不能从当前草稿取值。终态中明确失败的用户策略附带可选 `failedStrategyIds`，允许保留该策略有界的非法标量参数或重复类型供修正；标记必须唯一且属于保存配置，不放宽目录、结构、深度、数量或身份限制，后续成功运行移除标记。编辑和文件导入不写入，结果、运行 ID、编辑身份、图表选择和语言均不保存。损坏、不兼容或超出上述限制的记录回到默认配置，写入失败有简短提示。结果只存在当前页面，长期保存使用 `.strategy.json` 与 `.backtest.json`；后者保留原始提交 config、完整结果、全部候选及数据上下文，导入草稿使用该运行已验证的实际区间。

页面使用 `/runs/{runId}/events` 的单一 SSE 连接接收真实进度、策略状态及完成指标，结束后读取一次完整运行响应；断开订阅不影响计算，刷新可重新订阅未完成作业。计算失败诊断只给出可翻译的阶段、策略 ID 和运行 ID，不回传异常消息或内部字段路径。

SSE JSON 数据由 `RunProgressEvent` 契约定义，逐策略摘要使用 `RunStrategySummary`，两者生成 OpenAPI/前端类型并复用 `StrategyStatus`。终态事件不含未完成策略，非空终态进度必须完成全部计数；成功摘要必须有保存指标，失败/不可用摘要必须有诊断。前端读取同时验证所订阅 runId、progress/terminal 事件名和状态一致性，非法事件不得更新工作区。成功、活动与终态判断集中于同一前端状态模块，结果、导出、文件及运行控件共用；`empty` 仍只表示无作业。

HTTP查询运行、停止、候选详情和回测包的响应身份必须分别匹配URL请求的runId或candidateId；结构合法但身份不匹配时统一返回客户端invalid_response，不更新运行、曲线、明细或下载。候选读取失败保留此前保存曲线，正确响应可重试；不可只核对响应内各字段彼此相符。

标的元数据响应symbol须匹配请求代码经后端既有trim/upper规则规范化后的值；另一标的的币种不能写入共通设置。错误沿用invalid_response及弹窗退出校验，保留原草稿和结果，允许正确响应重试。

停止请求绑定发起时的运行 ID 和取消控制器；成功、失败响应均须确认仍属于当前任务。终态后晚到的停止响应不覆盖重跑结果、选择或清空状态，也不修改新任务的错误/锁定。当前停止失败仍可见且可重试，成功重试清除该请求错误，保存的策略诊断保持。SSE 在分帧前归一化 LF/CRLF/CR 行尾，处理 CRLF 跨网络包及 UTF-8 分片；收到终态立即释放响应体，不等待服务器关闭连接。异常 EOF/未完成终态帧仍报连接失败，不生成完成状态。合法行尾依据 [HTML 事件流解析规则](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)。

受理响应到达前的停止意图在获得 runId 后执行；先展示/订阅已受理作业，停止失败不得阻断订阅或丢掉运行。queued/loading/running 期间播放按钮显示同一 spinner 和真实阶段，停止可用；终态后取得完整结果前仍禁用编辑，停止入口撤下，几何槽位保持。所有生命周期均不生成历史运行条或状态面板。

选定结束日保持冻结，实际计算窗口以有效行情报价确定。若交易日已收盘但 Yahoo 尚未提供完整有效行情，回测窗口缩至最后完整报价日，不显示来源延迟警告。每段只缺一个交易日的行情缺口会从所有策略共用的交易日历中移除，不合成或前填价格；连续缺失两个或更多交易日仍阻断依赖该区间的策略。

`RunDataContext.dataProvenance` 保存已读取数据的去重排序来源 `sources`、最早日历截止日 `calendarAsOf` 和已加载行情快照中最早的最新报价日 `marketDataThrough`。任一已加载行情快照没有报价时，`marketDataThrough` 为 `null`。四类 CSV 都从保存上下文追加 `dataSources`、`calendarAsOf`、`marketDataThrough`；行情截至日期只表示行情报价覆盖，宏观和 SEC 数据的观察/公开日期仍由各自数据诊断说明。schema-1 快照的 dataFingerprint/dataProvenance/dateAdjustments 兼容字段是上下文的只读投影；不一致的导入被拒绝，旧无 dataContext 文件仍可读取。

## 模块接口与目录组织

数据结果携带独立 `SnapshotContext`：回测起止日、频率、目标会话和规范化版本。`compose_data_snapshot(MarketDataResult, macro_results)` 只合并相同上下文，并检查各缓存身份覆盖该上下文、宏观对齐日属于实际目标行情会话；来源/dataVersion 可不同，规范化版本必须相同。预热和宏观回看区间可以不同。运行层清洗缺口后显式重绑定结果上下文，原供应商缓存身份不改写。

`MarketDataResult.availableFrom` 为供应商可核实的首个交易日，未知或与真实报价矛盾时为 null，不由头部缺口推断。运行数据层把日期解析传入 `StrategyDataLoad.dateAdjustments`，worker 在加载后冻结到 `RunDataContext`；内核、基准和搜索使用同一 effectiveRun，原始 RunSnapshot.config 保持提交值。同一运行的日历、行情和调整必须一致。完成后的完整响应可按请求匹配关系同步草稿对应日期，未完成作业重连遵守同一规则；已编辑的其他请求不被覆盖。没有调整的响应不复制草稿。

POST /runs 验证并冻结配置后立即发布 queued/202，后台进入 loading 再调用供应商；加载期间没有伪造的数据指纹。停止从 queued 起可用，状态锁内检查取消并绑定上下文，迟到数据和候选不能覆盖 cancelled。已经发出的供应商请求依靠其超时结束，不阻塞停止响应。

`market.period_before_listing` 的安全详情包含可用首日、原请求起止日和建议起止日，前端只解析有效 ISO 日期，不自行推断上市时间。诊断操作复用既有字段导航通道；建议仅在代码和原日期仍匹配时写入草稿，否则打开日期编辑器，不改保存结果、不自动提交。预热需求仍由注册表/条件依赖计算；运行数据层按每条策略完整需求选择可恢复的共享起点，无法完整预热的策略保留独立不可用结果。

行情缓存指纹只包含请求行情窗口内的会话，不包含宏观陈旧设置；宏观缓存包含自己的回看会话和陈旧政策。fixture 结果同时含行情和宏观，故其缓存身份包含两类输入。未知本地解析/模型错误由运行层记录 `calculation_failed` 的安全阶段元数据；提供方网络错误与已知数据缺失分别返回结构化诊断，不能把程序错误伪装成网络失败。

建议目录按职责放置：`backend/app/catalog`、`config`、`data`、`domain`、`runs`、`export`；`frontend/src/features/config`、`strategies`、`runs`、`results`、`i18n`；统一表单控件放 `frontend/src/shared/ui`。这些是组织边界，不要求每个目录包装一个透传模块。领域契约只接收已物化的数据设置，不反向导入 catalog；注册表默认值与适用边界由 catalog/config 边界提供。数据供应商更换只改适配器，策略逻辑与 UI 契约不变。

前端组合层使用 `useWorkspace` 管理默认/上次运行配置、草稿和编号，使用 `useRunController` 管理提交校验、API/SSE、未完成作业重连、停止和锁定。两者共享既有 `WorkspaceState` 与纯 reducer，App 只组合 UI 与导航，不复制运行协议或结果推导。缺失 root 由启动边界显式报错；共享焦点、控件选择及错误样式使用语义颜色 token。

目录请求/重试/取消归属 `app/useCatalog`，响应式侧栏与移动视图归属 `app/useWorkbenchLayout`，诊断字段路径由 `runs/diagnosticNavigation` 纯解析为共享字段、策略/条件/搜索数组字段或日期恢复目标；App只执行打开、聚焦、显示侧栏等UI动作。表单字段标识和catalog元数据共用，不另建参数默认值或导航状态副本。

`ResultsCharts`只组合联动图表、共享交互与系列选择。`results/chart`中的纯系列模型一次读取保存资产/信号并归一比较曲线，坐标/日期轴、格式、主图、辅助图、工具栏和高亮hook各自负责展示；可用性/绘图/读数/交易点共用同一日期对齐对象。既有chartModel/viewport/markers/technicalIndicators/ChartCrosshair/useChartInteraction继续作为复用边界，不新增图表库、重新计算指标或建立第二套选择状态。

`StrategyRun.technicalIndicators` 保存启用条件实际使用的 MA/布林/RSI 序列及周期、布林倍数，信号模块直接复用自己的指标缓存，不进行第二次计算。每日样本仅包含运行日，预热或缺值为 null；布林的 value 为中轨，并保存上下轨。普通运行、最佳搜索结果及候选详情使用同一字段，进程内结果与回测文件保留原值；旧结果默认为空，不在前端补算。相同参数和完整样本去重后展示，选择策略控制所属指标，明细焦点和当前草稿不改变它们。MA/布林和价格使用同一价格起点，RSI 用自然单位的紧凑联动图；所有周期与原值读数在主图常驻区显示。可独立关闭 MA/BOLL/RSI 显示，价格隐藏时价格指标随之隐藏，结果收益线仍可用。

样式入口`styles.css`仅维护有序import清单；`styles/`按布局、控件、弹窗、策略、结果、图表及响应式边界维护，后置覆盖保持历史cascade顺序。语义主题token只有一个定义。`i18n/{ja,zh}`按common/strategies/results/diagnostics维护无重复机器键，`messages.ts`只组合词典及提供translate/interpolate/unitLabel；改变文案时同步日中键，静态审查读取实际模块全量。

成交解释字段由统一账本在每次成交处采集，Trade保存可选现金/总持仓的前后值及基准/成交价格；普通/搜索/基准复用该契约。CSV及离线导出读取保存字段，不再计算交易。旧结果缺字段保持空值，executionPrice若存在必须与price一致，读取边界保留精确Decimal比较。

`savedResultConfiguration`是冻结策略和已保存搜索候选参数的读取边界，报告、图表及成交解释共用；候选只覆盖保存的搜索维度。`tradeExplanation`从前一个保存交易日读取条件树、实际三态、观察值和卖出档位，不重新计算或取当前目录默认值；旧信号缺少指标语义时保留原值。`dataInformation`按保存交易日去重宏观/估值观察值，FALSE也算有数据，unavailable/空观察值不计覆盖；来源、实际区间和币种缺失时显示占位，不假定供应商或零覆盖。

`PerformanceAnalysis`由纯metrics边界保存，普通策略、基准和搜索传入同一冻结AnalysisSettings。分析值、计算口径、计数与不可用原因一起冻结；UI只格式化，旧文件缺分析不自行补算。汇总/搜索CSV字段从后端模型生成并追加在旧列末尾，离线读取相同契约。`PerformancePanel`在结果详情的独立tab分组呈现，不增加比较表列；利率字段复用注册表ParameterField。精确十进制读取边界校验分析范围，避免JS浮点把极小负数/越界数值误接受。

### 训练/测试搜索（catalog-v15）

搜索增加`search.optimizationMode`（full_period/train_test）和可空`search.trainEndDate`。只有分段模式要求分割日在请求区间内且早于结束日。模式、日期和边界来自唯一注册表；v12–v14文件只对可编辑草稿补充默认值，保存结果不迁移、不重算。

SearchResult保留Train排名，另存trainPeriod/testPeriod、每行testResult摘要与独立resultId，以及四个同期periodBenchmarks。StrategyRun.evaluationPeriod标明所属窗口；详情、曲线、成交解释、期间绩效、CSV和PNG都读取该保存窗口。两个窗口均从零现金/持仓开始，不跨界注资或成交；指标预热可使用窗口开始前的当时已公开行情。交易与绩效定义仍见主设计稿。

普通策略、基准及搜索均经`app/simulation.py`纯计算组合进入同一信号/账本/指标模块；外层负责数据、取消、异常、保存和身份。分段调度仅改变评估区间与注资计划；测试结果和失败不改变训练排名。局部期间比较只使用同窗口保存基准，普通完整期间结果不冒充局部期间曲线。

内部边界：`signals/evaluate.py`组织条件树及逐日输出，`leaf_evaluation.py`求值原子条件，`observations.py`读取as-of观察和装饰缺失诊断，`context.py`提供快照上下文及每策略独立缓存。`data/run_planning.py`负责日历/预热/有效区间，`providers/yahoo_frames.py`纯解析行情与宏观响应；Yahoo适配器保留网络、元数据和供应商异常，作业层组合加载结果。方法版本和指纹不因等价搬移改变。

`ModalShell`共用原生打开/销毁、Escape及背景点击边界；编辑器传入合法关闭动作并保留缓冲、校验、币种及提交，结果工具显式启用卸载返回焦点。`StrategyAddMenu`负责菜单键盘/关闭，`StrategyCard`只展示并发送操作，导航器维护策略和焦点。基础对象判断位于`shared/lib/record.ts`，API错误读取位于`api/errors.ts`，不合并传输边界或错误类。

参数比较仅从保存SearchResult读取：热图选择两个不同数值轴，邻域选择一个轴，其他维度固定为明确配置值。轴按精确数值排序，每轴20项分页；同一阶段读取XIRR/Sharpe/Calmar/最大回撤，null保持不可计算，不插值。单元点击复用保存候选身份/详情入口，Test不影响Train排名。邻域显示整个已配置截面，不自动把尖峰判定为过拟合。

策略卡片保留直接编辑和删除，更多操作可复制自定义策略或恢复默认。复制深拷贝params/rules，使用新ID及单调自定义序号，遵守目录数量限制，固定策略不可复制；不复制结果。恢复默认需原生modal确认，调用目录创建入口恢复preset/Custom模板，保留实例ID和序号。确认、取消及复制均不修改已保存运行、曲线/结果选择，不自动保存编辑配置。

工作区快捷键复用对应按钮函数：Ctrl/Cmd+Enter运行，E在有终态结果时保存回测文件、否则保存当前策略文件，I打开导入文件选择。输入/可编辑区域、原生dialog、忙碌/禁用、重复按键及已处理事件不触发；不消费其他组合键。Escape仍交给现有dialog校验/关闭，不能绕过错误退出保护。快捷键不新增提交/导出/导入状态。
