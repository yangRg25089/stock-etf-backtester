# 股票与 ETF 策略回测器设计

## 目标

构建一个仅在本机运行的股票与 ETF 回测 Web 应用，将两份现有 notebook 的策略和可调参数带入可重复使用的界面。首次打开即呈现 VIX 信号定投策略，使用 QQQ 和 notebook 风格的默认参数，可直接运行；用户可以追加策略、调整任意参数，并选择运行当前策略或全部已启用策略。首版实现利率与历史 PE 信号。界面默认日文，并可切换为中文。

本应用用于历史模拟，不连接券商、不下真实订单，也不提供投资建议。

本文件是交易规则、数据口径、错误处理和验收条件的唯一依据。[复用与组织规范](../../design/reuse-and-organization.md)集中定义策略目录、参数所有权、界面组件、模块接口和工作顺序；[V1 画面设计源](../../design/backtest-ui.html)呈现这些规则。[审查指摘对照](../../design/review-resolutions.md)仅记录每项问题的归属，不新增规则。重复出现的同类功能只能引用同一条定义，不另建并行规则。

## 方案与边界

采用本地 FastAPI 服务与 React/TypeScript 前端。前端通过共享策略目录和参数注册表配置实例，FastAPI 使用同一注册表校验并编排作业。行情、VIX、利率、SEC 财务事实和 ETF 持仓各有数据适配器；回测模块只读取规范化快照，不直接调用供应商。绩效、搜索、基准与导出复用同一账本和结果快照，模块接口与依赖顺序见复用规范。

主要边界：

- **配置与校验**：共享回测范围、标的、月度注资和数据有效期；每个策略实例拥有自己的交易规则与信号参数。注册表是类型、默认值、单位、范围、适用策略和字段分组的单一来源。
- **数据适配**：供应商字段转换、交易日期对齐、单位归一、缓存和数据可用性诊断。原始响应不得泄漏进策略内核。
- **策略执行**：每条策略用同一注资日历、信号三态、成交顺序和资金账本；输入验证后的配置及时间对齐的数据，输出每日完整总资产与交易。单条失败不抹掉其他成功结果。
- **绩效与结果**：搜索候选、普通策略和基准调用相同指标模块；状态、错误码、数据来源和导出由不可变运行快照衍生，前端只呈现结构化结果。

运行链路为：编辑共享设置与策略实例 → 确定当前实例或全部已启用实例 → 冻结所选实例的配置 → 对每个所选实例独立校验参数与依赖 → 获取规范化数据快照 → 独立运行各策略与共用基准 → 计算指标/状态 → 显示并导出同一快照。只运行当前实例时，未选实例的错误不得阻断它；多实例运行时，某一实例的错误不得阻断其他实例。数据缓存仅用于减少重复下载；缓存键区分供应商、代码、频率、日期、数据版本和价格口径，并使用有界 LRU 与显式刷新入口；结果展示数据截至日期。

| 回测起始日 | `2020-01-01` | 可修改 |
| 回测结束日 | 最近一个有完整行情的交易日 | 以可立即运行作为默认；可修改 |
| 月度注资金额 | `100` | 使用标的报价币种；可修改 |
| 月度注资日 | `1` | 全部策略共用的注资日历；可修改 |

这里的“VIX 信号定投”是可编辑的策略预设名称，不表示 VIX 代码、阈值或开关固定。`vix.buyEnabled`、`vix.symbol`、`vix.buyThreshold` 和相关买入次数均属于该策略实例的可编辑参数。界面保留稳定的策略类型名称，并显示当前参数摘要（例如 `VIX: ^VIX ≥ 25、月間最大 1 回`）。如果用户关闭 VIX 信号，实例仍保留 `vix_dca` 身份，不静默转换成另一种策略；界面明确显示「VIX シグナル無効」，其余注资、安全阀和空买入信号规则按统一账本执行。

按月将注资加入策略现金；达到 VIX 条件时投入可用择时现金。交易所实际月末若现金达到安全阀阈值则强制投入。默认月初注资保持 notebook 的意图，但配置中的注资日必须真正生效，不保留其 `day <= 7` 硬编码。月度定投和一次投入基准使用完全相同的有效计划本金。复权价格用于策略模拟；PE 使用不同的估值价格字段，不混用。

界面把这条策略及其参数作为首屏主体。其他策略从统一目录手动加入；每条实例可编辑、停用、删除，并可按相同目录重新添加。共享的标的、日期和注资计划只在页首编辑；信号、安全阀和卖出属于实例。切换当前编辑策略不改变启用状态，也不重置参数。

V1 保留已认可的简约布局：页首语言切换与共享设置；主体左侧编辑当前策略，右侧列出全部已添加策略并提供完整的 7 类添加目录；右侧仅有一个运行范围分段选择器和一个运行按钮；底部为聚焦结果的绩效、曲线、比较表和交易记录。列表行名称切换编辑对象，唯一启用开关位于列表行；编辑器只显示状态。窄屏改为单列，不隐藏核心操作。

## 统一日历、账本与成交

共享注资日历生成器供全部策略、基准及搜索候选复用。用户起止日期含边界；指定未来结束日时，将有效结束日定为最近完整交易日并提示实际区间。注资日为 1..31，短月截到月末日历日；若该日不是交易日，取同月其后的首个交易日，若没有则取同月最后交易日。只保留有效回测区间内的计划，月中开始不补缴此前应注资额，月中结束不预缴未来额。一次性投入的本金等于同一注资日历中有效计划金额的总和，在首个回测交易日投入；它有提前投入未来计划金额的资金时点假设。区间无有效注资时提示调整计划，不能算出伪造的收益率。

每条策略使用同一账本：`总资产 = 现金 + 择时持仓价值 + 固定定投持仓价值`。固定比例定投只分配当月注资，并始终计入总资产、曲线、收益、回撤和搜索排名；卖出只动择时持仓。固定比例为 100% 时，和相同注资日历的普通 DCA 总资产一致。无论现金是否为 0，每个交易日都估值并评估可能的卖出。

策略模拟价格沿用 notebook 的调整后收盘价；持仓份额和成交价为该复权口径下的模拟值，不重复派发股息。PE 使用独立估值价格。依赖当天收盘形成的信号在下一交易日收盘成交；回测最后一日形成而不能在区间内成交的信号记录为未执行。这个因果顺序有意不同于 notebook 的同日收盘信号/同日收盘成交，因此不承诺与源 notebook 逐数字相同。

每日顺序统一为：注资 → 计划型买入（固定定投/DCA/首次一次投入）→ 前日信号卖出 → 前日信号买入 → 交易所实际月末安全阀 → 总资产估值 → 当日收盘信号。卖出执行日抑制同日择时买入和安全阀回补，固定定投计划照常执行。安全阀只在实际交易所月末检查，不能把回测在月中截断的最后一日当月末。

月度信号买入次数以成交的年月计；固定定投与安全阀不占次数。两级 VIX 卖出按较低 VIX 档优先；多个卖出条件同日命中时取最大卖出比例，不相加。买入开关与卖出开关独立：即使 RSI/VIX 买入关闭，启用的相应卖出规则仍需要该序列。布林卖出的 VIX 上限从原硬编码 20 改为可调字段。

## 信号与统一缺失规则

| 条件 | 有效数据上的判断 |
| --- | --- |
| VIX 买入 | `vix >= threshold` |
| RSI 买入/卖出 | `rsi <= buyThreshold` / `rsi >= sellThreshold` |
| 均线偏离买入 | `(simulationPrice - MA) / MA * 100 <= deviationPct` |
| MA 趋势 | `simulationPrice > MA` 买入；买卖变体在 `simulationPrice <= MA` 卖出 |
| 布林买入/卖出 | `simulationPrice <= lower` / `simulationPrice >= upper && vix < sellVixCeiling` |
| 利率买入 | 归一成百分数值后 `ratePct <= thresholdPct`；默认阈值 `2.5` |
| PE 买入 | 有效正 PE 且 `pe <= threshold`；默认阈值 `25` |

RSI 使用 notebook 的滚动算术均值，MA 使用简单均值，布林带使用样本标准差；指标方法版本化，不在同类策略中复制不同实现。技术指标只读当日及以前的行情，可请求回测区间之前的预热行情；预热期不注资、不计绩效。

每个被启用的买入或卖出依赖在每个需要评估的交易日输出 `true / false / unavailable` 与结构化原因。统一采用严格依赖：任何必需信号在该日不可用，整条依赖它的策略为 `unavailable`，不输出不完整收益；其他策略继续。AND/OR 只组合有效布尔信号，OR 不允许静默跳过缺失的 PE 或其他启用信号。禁用信号不形成依赖；空买入信号集合为 false，注资/安全阀规则仍可运行。运行前诊断与结果诊断使用同一状态码与数据依赖解析，不为 PE 另设例外。

## 数据源与缺失处理

行情、VIX、利率优先用 Yahoo Finance/yfinance；公司财务事实优先用 SEC CompanyFacts/XBRL；ETF 历史持仓优先用 SEC N-PORT 公开申报。供应商适配器向回测模块提供统一的报价币种、交易所日历、`simulationPrice`（模拟总回报价）、`valuationPrice`（不含分红调整且与 EPS 拆股基准一致的估值价）、数据时间戳、来源及数据指纹。两种价格无法可靠区分时，依赖 PE 的策略不可用，不擅自代用。利率统一为百分数值；不能只凭 `^TNX` 代码猜测转换倍数，无法确认来源单位时要求明确设置或报单位错误。Yahoo 适配器依据 [yfinance PyPI 发布页](https://pypi.org/project/yfinance/)（当前验证版本 1.7.0）及其 [`Ticker.history` 实现](https://github.com/ranaroussi/yfinance/blob/1.7.0/yfinance/scrapers/history.py)、[quote 实现](https://github.com/ranaroussi/yfinance/blob/1.7.0/yfinance/scrapers/quote.py)：显式关闭自动/回溯调整，按 inclusive `start`、exclusive `end` 请求，只有明确的调整收盘价与收盘价时分别映射为两种价格口径；币种必须来自明确行情元数据，字段缺失或冲突均不可用，不假设 USD。

行情价格不前向填充或插值。运行编排可把每段仅缺少一个交易日的行情缺口从共享交易日历中移除；所有策略、基准和搜索候选都跳过该日，不合成价格，也不因此显示警告。连续缺失两个或更多交易日仍按必需行情不可用处理。动态结束日期直接以行情快照中的最后有效收盘日为准，之后尚未发布的日历交易日从本次运行日历中剔除，不显示来源延迟警告。VIX/利率可使用当时已经发布且不晚于目标交易日历 3 个交易日的最近观测，该上限是可调共享数据设置。宏观规范化保留源观察日、观察时间、可核实的发布时间和来源单位；对齐后的交易日另存，不覆盖任何源日期。由于交易日历不提供每个 session 的收盘时点，无法核验时同一日历日期的宏观观测一律从下一交易日开始使用，不根据供应商时间戳推断同日收盘前可用。as-of 选择不得早于源数据可用时间，陈旧度按交易所 session 计数，超过设置的观察不生成对齐值。财务与持仓按公开时间进行 as-of 查询，分别默认不晚于财务报告期结束后 550 个日历日、持仓快照后 180 个日历日，两个有效期亦可调并进入运行快照。过期、币种不一致、数据缺失或交易区间无重叠都通过同一诊断机制处理。

每项 SEC 事实保留报告期、申报/更正标识、实际公开可用时间及来源版本。只在已公开后参与信号，后续更正不回填此前日期。对于只有公开日期、无法确认具体日内时间的记录，从下一交易日才视为可用；连公开日期也无法核实则不可用。基金持仓不能用今天的组合回填历史。[SEC CompanyFacts 接口](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)和[SEC N-PORT 公开数据范围](https://www.sec.gov/data-research/sec-markets-data/form-n-port-data-sets)是首版免费来源，部分标的与日期缺少可用 PE 是预期限制。

### 个股 PE

在交易日 t，选择当时已公开的最近合格十二个月 diluted EPS：可用时用最近四个已披露、期间连续且不重叠的独立季度 EPS 合计，标明它是 `quarter_sum_estimate`；或使用最近已公开的完整年度 EPS，标明 `annual_report`。依据实际报告期结束日选择最新的合格口径，若结束日相同则优先年度报告。年度回退值保留年度期间和数据龄期，不假称为最新季度 TTM。不能直接相减累计 YTD EPS 还原季度，因为各期间使用的加权平均股数不同，季度 EPS 之和也不必等于全年 EPS。[SEC 申报中的说明](https://www.sec.gov/Archives/edgar/data/1174850/000117485025000023/R11.htm)。

EPS 与 `valuationPrice` 必须为同一股票类别、币种与拆股后的每股基准。若 EPS <= 0、基准不匹配、无合格口径或超有效期，则 PE 不可用；否则 `PE = valuationPrice / EPS`。负 PE 不得通过 `PE <= 25`。

### ETF 持仓 PE 估算

动态标的中，仅有可核对历史直接股票持仓的普通实物多头股票 ETF 可计算“股票持仓 PE 估算”；债券、杠杆/反向、合成及需要穿透其他基金的 ETF 不推算。依赖能力检查及公开申报数据，而不是固定允许代码名单。估算标明股票部分占基金比例、持仓快照日期、覆盖率、EPS 口径，不标为整个 ETF 原生公布的 PE。

令 `w_i` 为历史快照中成分 i 占全部直接股票持仓市值的权重，`K` 为身份、财务与价格均匹配的成分集合，`C = sum(w_i, i in K)` 为有效覆盖率。要求 `C >= minCoverage`，默认 0.80，可调；未知成分的盈利不当作 0，而对覆盖部分重归一。`earningsYield = sum((w_i / C) * EPS_i / valuationPrice_i, i in K)`；它保留有效亏损公司的负盈利贡献。若收益率 <= 0，则估算 PE 不可用；否则 `estimatedPE = 1 / earningsYield`。持仓权重取公开快照的已披露权重并维持到下一份可用快照，属于明示估算。

个股买入 PE 需要正 EPS；ETF 聚合却必须包含有效负 EPS，因此复用的是有符号每股盈利收益率计算，不可把“个股 PE 不可用”的结果直接当作 ETF 成分覆盖缺失。

### 策略级错误与状态

每条运行的策略独立返回 `queued | loading | running | completed | completed_with_warning | unavailable | failed`，状态和诊断码在前后端、列表、结果和 CSV 共用。参数错误、供应商请求错误、所需数据不可得和策略计算异常明确区分；数据不可用不能显示为零收益。任一所需 PE/VIX/RSI/均线/布林/利率缺失，只影响依赖该数据的策略；其余成功结果保留。源数据质量提醒与估值方法标签可使已完成结果带警告，但不能用警告绕过必需数据验证。

## 结果体验

- 全部策略、基准及搜索候选从完整总资产账本和统一指标模块计算：`totalContributed = 实际有效注资之和`、`endingEquity = 期末总资产`、`netProfit = endingEquity - totalContributed`、`returnOnContributions = endingEquity / totalContributed - 1`、`capitalMultiple = endingEquity / totalContributed`。百分比回报与资产倍数分开命名，不能把 `endingEquity / totalContributed` 标为盈利率。
- 年化回报对策略和两种基准均用各自实际外部现金流与终值算 XIRR，年化日数按实际天数/365：月度策略/DCA 按有效注资日记流入，一次性投入按首日全部本金记流入，不能把提前投入又记为后续月度流入。无唯一有效解时只将 XIRR 标为不可用并附原因，不伪造年化值。最大回撤从扣除外部注资影响的单位净值序列计算；每日 drawdown 用不大于零的比例表示，汇总 `maximumDrawdown` 存其正向绝对值。贡献在计划买入日收盘按当日外部注资前的单位净值发行份额，避免将收盘成交前的新资金误记为当日收益。`relativeToDca` 表示同币种的期末资产差额 `endingEquity - dcaEndingEquity`，只比较同资金预算、有效交易期间及数据快照的月度 DCA。所有中间计算保留精度，显示时才舍入。
- 月度 DCA 和一次投入作为默认必选自动基准，不出现在策略添加菜单；后端目录仍保留七类，历史用户实例的独立身份/结果继续可读。同参数计算可以复用，但不能合并角色与身份。搜索默认按 `endingEquity` 降序排列，并列时先比较较小的绝对最大回撤，再按稳定候选序号。不同参数维度和取值均经过普通策略同一注册表与校验；热图的二维切片固定其余维度，不静默把不同组合混算。显示组合数量并限定一个可调上限；无效候选保留原因、不参加排名。
- 每次运行保存不可变配置、数据指纹和结果；本机 SQLite `RunStore` 持久化运行响应与幂等记录，服务重启和页面重新打开后可恢复最近运行及其导出。恢复从已保存响应读取，不重新计算、不重新下载数据。服务重启时仍处于 `queued/loading/running` 的实例改为带明确诊断的 `failed`，不假装可从进程中断处续跑。当前草稿修改、停用、切换编辑对象后，旧结果保留原身份、保存身份可从按需信息入口查看，标的/期间不在各卡片重复；右侧不显示草稿校验/旧输入提醒，也不清除已保存运行诊断。重置只清空客户端当前显示结果/错误，记住已清空的 runId，刷新不恢复同一结果；不删除 SQLite 记录，新运行仍可恢复。KPI、资产/回撤曲线、交易记录和导出跟随当前聚焦的结果，而非当前编辑对象。图例显隐只改变图表；零交易是成功的空交易表，与不可运行不同。
- SQLite 对冻结策略参数使用带版本的私有类型编码，保证十进制阈值和金额保存/读取后仍是原数值类型；API 快照仍使用原有 JSON 契约。页面通过单条 SSE 进度流订阅运行状态，完成后读取完整结果一次；页面关闭只取消订阅，不取消持久化的后台运行，重新打开可恢复并重新订阅。
- 动态结束日期直接落到数据快照的最后有效收盘报价；之后尚未发布的交易日不进入运行日历，也不显示延迟警告。每段仅缺失一个交易日的价格缺口会从所有运行共享的交易日历中剔除；行情本身不前向填充或插值。连续缺失两日及以上仍不可用。
- 价格图以与 `simulationPrice` 同口径的规范化收盘价绘制走势折线，不显示 K 线；资产收益曲线标记已保存交易的日期和方向。资产、回撤、价格和 VIX 图绘制网格、日期/数值刻度及币种/百分比/点数说明。保存结果可保留可选 OHLC 来源值，但图表只呈现收盘价走势，不合成价格。价格与总资产始终在同一张核心比较图中：价格按首个有效收盘价归一到 100；总资产曲线按用户确认使用 `100 * totalAsset / totalContributed`，其中每日累计本金由共享现金流/指标模块输出。首次注资前不画资产收益点，亏损/资产为零可显示；不再按首个收益值二次归一。单位净值仅继续用于现金流调整回撤，不作为本图的资产收益线。没有累计本金字段的旧快照不由前端推算注资，明确显示资产收益曲线不可用并提示重新运行。图例保留原始序列名和币种，只隐藏价格时资产主图仍在，至少保留一条可用主线；交易标记仅落在有效且可见的资产收益线上。十字定位取最近保存日，纵线跨图同步，横线属于当前图，左上同时提供价格/总资产金额、累计本金与相对指数/自然单位指标；零本金日保留已知原始金额，只有相对指数不可用。Shift+左右键逐日查看、Escape/离开收起，缺失值不插值；图上有清楚的 100 起点参考线。仅保留联动视图，分割模式及相关控件/状态完全删除。回撤/VIX 按自然单位紧贴主图底部，辅助图高度减半，与主图同宽、竖向网格对齐；辅助图 figcaption 与局部图例/高亮逻辑完全删除，保留自然单位数值刻度及 SVG 可访问名称；日期刻度、日期轴标题和定位日期标签在独立底部轴显示一次，不占任一辅助图绘图区。所有辅助图绘图区等高，显隐或策略切换不会压缩最后一个图。价格和总资产始终在核心比较图，不将指标再归一叠到收益纵轴。所有图表共享一个日期窗口，在任一图表拖动或缩放都会同步更新其它图表，且可恢复完整历史范围；图表范围内的滚轮和触屏手势由图表处理，不应同时触发页面滚动或浏览器缩放。交互和信息分层参考 [moomoo 图表帮助](https://www.moomoo.com/us/support/topic3_33)、[自定义叠加](https://www.moomoo.com/us/support/topic3_131) 及[指标参数管理](https://www.moomoo.com/us/support/topic3_525)，不复刻品牌样式；起点 100 是本产品为跨量纲比较采用的相对口径。信号结果保存实际宏观观察值和单位；VIX 图使用不可变结果里的观察值、VIX 代码和阈值，不读取当前草稿或重新请求供应商。
- 结果页区分无作业、运行中、全部失败、部分成功、完成但警告及完全完成；错误/覆盖率采用统一状态码和翻译。独立运行条/状态面板及重复状态列表在所有生命周期完全删除，运行进度归属播放按钮和辅助技术播报，每策略状态在比较表呈现，真实错误/保存诊断去重后在结果详情中显示且折叠后仍可读。未有完成结果时 CSV 操作禁用；成功但零交易时交易 CSV 仍可导出表头。绘图可整体折叠；交易明细直接显示表格，完全删除专用显隐控件、状态及 UI 参数注册项，不影响计算或原始结果导出。
- 资产收益曲线标记买卖交易，价格同主图，VIX/回撤在其底部按自然单位联动显示。可导出汇总、每日资产、交易和搜索结果四种 CSV，原字段键、ISO 日期、原始数值及独立币种列保持稳定，每日资产追加 `totalContributed` 列；四类 CSV 从不可变运行快照附带来源 `dataSources`、日历截止日 `calendarAsOf` 和行情最新报价日 `marketDataThrough`，后者只表示行情报价覆盖，宏观/SEC 日期仍以各自诊断为准。默认日文，中文可切换；可见标签、状态和错误来自同一词典，语言切换不改变配置或结果。

## 测试要求

- 字段契约测试：两份 notebook 全部显式输入映射到唯一注册键；普通/网格使用同一边界、单位、依赖和错误字段路径；目录包含全部七类且删除后可重新添加 VIX。
- 日期与交易测试：31 日、月底假期、起止日落在月中、未来结束、年月切换；信号 t 收盘后只在 t+1 执行；零现金仍估值/卖出；同日卖出抑制择时买入；固定比例 100% 与 DCA 等值。
- 信号与估值测试：所有阈值边界、AND/OR 对同一种 unavailable 的处理、技术指标预热、买卖开关独立依赖；财务披露日和晚于收盘的事实不前视；不从累计 EPS 差分；个股非正 EPS、ETF 负贡献及 80% 覆盖重归一、拆股/币种与两种价格基准。
- 指标与结果测试：普通/搜索/基准同账本和指标；注资回报与资产倍数不同；XIRR/回撤含现金流；草稿修改不改变旧结果；部分策略失败保留成功结果，CSV、图表、表格都读同一结果快照。
- 持久化与请求测试：领域参数在 SQLite 版本化编码、旧格式恢复及 API 序列化之间保持值/类型约定；真实 QQQ/VIX 的 SQLite API 回归须验证真实 VIX 信号和成功结果。运行提交与页面恢复分别只建立一个可取消 SSE 订阅，终态后只取一次完整运行响应；断连、重连、404 和部分策略失败均保留正确作业语义。
- 界面测试：单一运行入口、启用与编辑独立、共享资金字段只出现一次、展示偏好与导出独立、空/零交易/失败态、语言切换与 320/768/1024px 无裁切。
- 纯计算边界测试使用固定行情、交易所日历和 SEC 申报 fixture，便于精确断言交易规则。默认 Yahoo 获取/规范化/运行链路必须有调用真实供应商的回归测试，以真实 QQQ 与所选波动率指数观测作为通过依据；mock、fixture 和单独 smoke 不能代替这项门禁。实时数据断言只检查数据可用、身份/日期/币种/信号状态，不锁死当前行情数值。
